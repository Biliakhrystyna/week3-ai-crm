# Cinema Booking System

Система для керування кінотеатром, що дозволяє адміністратору керувати фільмами, залами та сеансами, а клієнтам — бронювати квитки через AI-агента.
## CRM Entities


| Entity | Fields |
|--------|--------|
| **Movie** | title, genre, duration |
| **Hall** | name, capacity |
| **Screening** | movie_id, hall_id, start_time, price |
| **Customer** | name, email, phone |
| **Booking** | customer_id, screening_id, seat_number, booking_time, status |
| **User** | email, role |

## Зв'язки між сутностями

У системі використано зв'язки типу **один-до-багатьох (1:N)**:

- **Movie → Screening (1:N)**  
  Один фільм може мати багато сеансів, але кожен сеанс належить лише одному фільму.

- **Hall → Screening (1:N)**  
  Один кінозал може використовуватися для багатьох сеансів у різний час, але кожен сеанс проводиться лише в одному залі.

- **Customer → Booking (1:N)**  
  Один клієнт може здійснити багато бронювань, але кожне бронювання належить лише одному клієнту.

- **Screening → Booking (1:N)**  
  Один сеанс може містити багато бронювань, але кожне бронювання стосується лише одного сеансу.

## Нормалізація бази даних

Схема бази даних відповідає **третій нормальній формі (3NF)**.

Під час проєктування були дотримані такі принципи:

- кожна сутність зберігає лише власні дані;
- кожна таблиця має первинний ключ (`id`);
- зв'язки між сутностями реалізовані за допомогою зовнішніх ключів (`movieId`, `hallId`, `customerId`, `screeningId`);
- усі неключові атрибути залежать лише від первинного ключа своєї таблиці.

## Уникнення дублювання даних

Для уникнення дублювання інформації між таблицями використовуються зовнішні ключі замість повторного зберігання однакових даних.

Наприклад:

- сутність **Booking** містить лише `customerId` та `screeningId`, а не ім'я клієнта, назву фільму чи назву залу;
- сутність **Screening** містить лише `movieId` та `hallId`, а інформація про фільм і зал зберігається у відповідних таблицях;
- дані про фільм (назва, жанр, тривалість, рейтинг) зберігаються лише в таблиці **Movie**;
- дані про клієнта (ім'я, електронна пошта, телефон) зберігаються лише в таблиці **Customer**.

Такий підхід забезпечує цілісність даних, спрощує їх оновлення та зменшує надлишковість. Наприклад, якщо зміниться назва фільму, її потрібно оновити лише в таблиці **Movie**, і зміни автоматично будуть відображені для всіх пов'язаних сеансів і бронювань.
